Code review / current working tree

Keep the engine. Rebuild the conversation surface.

Phi has a workable session and streaming foundation. Its main risk is the renderer: long conversations stay mounted, while one large app component coordinates most of the product. Replacing UI components alone will not fix scrolling.

Scope: renderer, sidecar, Electron, tests and packaging. Based on code inspection and the previously captured scroll trace, not a new runtime profile. No PRDs used. Application code was not changed.

Decision

Freeze this branch as a prototype. Build a narrow conversation flow on a new branch. Reuse the Pi session integration, API contract, stream reducer and tested helpers. Choose a component library for presentation, then virtualize the transcript before adding visual detail.

Findings, in order

  1. Long-session scrolling is the first blocker. Every turn is rendered with turns.map inside a full-height scroll container. There is no transcript windowing. The earlier trace recorded 107 dropped scroll frames and about 12,600 layout objects. Memoization and a new UI library do not remove those objects. Start with variable-height turn virtualization and test with a real long session; preserve bottom anchoring and expanded tool state.conversation.tsx · chat-viewport.tsx
  2. App coordination is too concentrated. App.tsx is 1,371 lines; the composer is 858 and sidebar 889. Session selection, drafts, queue draining, model changes, errors, tabs and keyboard actions meet in the app root. Extract workflow boundaries as the new flow is built, not by copying these files into a new shell.App.tsx · composer.tsx · sidebar.tsx
  3. The prompt lock has a gap before it starts. The sidecar checks isPromptActive, then awaits a Git snapshot before assigning activePrompt. Two requests for the same session can pass the check during that await. Reserve the session before snapshot capture and cover concurrent prompts with an integration test. Runtime cleanup also checks activity before this reservation exists.server/index.ts, /api/prompt and cleanupRuntimeRegistry
  4. Undo needs a file-safety test before being treated as stable. Restoration uses git checkout <tree> -- <paths>, which also writes the index. The current conflict check uses a worktree diff. Test staged changes, untracked files and partial restore failures against a temporary Git repository before promising that undo leaves unrelated work intact.server/index.ts, restoreWorktreeToTree
  5. Desktop boundaries need explicit hardening. The window has context isolation and Node integration disabled, but sandbox is disabled. There is no visible navigation guard or content security policy, and the localhost sidecar has no request authentication. Keep the narrow preload bridge, then review external navigation, permissions and local API access before distribution. This is a risk assessment, not a demonstrated exploit.electron/main.ts · server/index.ts · index.html
  6. Health polling is duplicated. useHealth creates one interval that runs while fatal and another that always runs, so failures trigger two checks every three seconds. Keep one polling loop and prevent overlapping requests.useHealth.ts

What is worth keeping

  • The Pi SDK and JSONL session boundary. Sessions have one source of truth. The sidecar already separates per-session live runtimes and does not stop a prompt when an SSE client disconnects.
  • The stream pipeline. The SSE parser, pure reducer, per-session store and useChat buffering are useful seams. Keep their behavior and tests; simplify orchestration later.
  • The testable domain helpers. Path safety, navigation selection, provider input, queue ordering and tab behavior have unit coverage. Keep these tests as a migration guard, not as proof that end-to-end flows work.

Start here

  1. Preserve the prototype. Resolve the current uncommitted conversation changes before branching. Confirm the recent collapsible crash fix in a running session. Do not carry the conversation presentation code into the new surface by default.
  2. Establish a small vertical slice. Open a persisted session, send a prompt, stream text and tool output, stop, continue, and use a composer. Leave themes, extra panels and presentation polish out of the first pass.
  3. Set the performance gate immediately. Render a long real transcript with a virtualized turn list. Measure dropped frames, mounted nodes and memory while scrolling and streaming. Compare against the earlier trace rather than judging only a short session.
  4. Protect behavior at the boundary. Add sidecar integration tests for concurrent prompts and navigation/file restore, then an Electron smoke pass for packaged loading and API reachability. Separate service routes from server/index.ts only where those tests need seams.
  5. Adopt a UI library deliberately. Use it for accessible primitives and consistent states. Keep Phi-specific session and stream semantics outside the library. Choose the library after the vertical slice proves scroll performance.
